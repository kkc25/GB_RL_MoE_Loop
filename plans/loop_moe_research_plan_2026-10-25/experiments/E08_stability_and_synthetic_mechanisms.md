# E08：充分状态、延迟收益与循环稳定性的合成机制实验

**定位：**低成本验证数学机制与代码正确性的独立路线；不能单独替代真实语言建模实验。先运行 CPU 精确反例，再按主线遇到的问题选择一两个学习实验。文献和方案截止：2026-10-25。

**硬件：**CPU 足以完成全部有限枚举与代数实验；学习型原型至多占用 1 张 RTX A6000。通常可用的其余 2–4 张卡继续主线训练。最多 8 张卡时也无需把这些小模型做专家并行。

**本次完成范围：**已经执行若干代数与计数复算，见 `../theory/verified_toy_calculations.json`。以下神经网络训练、计时和统计检验是待执行方案，没有虚构结果。

## 1. 科学问题与可证伪假设

| 子任务 | 假设 | 阴性结果如何解释 |
|---|---|---|
| A：状态充分性 | 仅在状态被压缩、动作集依赖历史或函数类有限时，记忆才有优势 | 完整充分状态下无优势属于预期，不是失败 |
| B：延迟收益 | 两步价值预测能恢复贪心错失的序列收益 | 若已知合成环境都不能恢复，先修实现和训练 |
| C：资源竞争 | 硬容量修正保证可行，价格改善分配目标 | 价格无增益则保留硬调度，删去博弈复杂度 |
| D：循环稳定性 | 有针对性的稳定化能控制路径爆炸而不毁掉任务信息 | 只稳范数不稳任务分数，说明收缩过强或目标错位 |
| E：因果与预算审计 | 规则满足前缀不变性与真实调用账本 | 任意违反都必须阻止该实现进入 LM 主表 |

不能以“合成任务有收益”推断自然语言必有收益；这些任务用于验证一个控制器是否具备声称的能力，或精确否定过强理论主张。

## 2. 子任务 A：三种历史价值必须分开

### A1. 完整充分状态的阴性对照

构造有限时域 MDP：状态由一个整数节点、轮数和剩余预算组成；\(E=4,H=4\)，转移表固定，终点损失由终点状态唯一确定。每个动作成本取 0、0.02、0.05 三种配置。随机生成 20 个转移表，全部有限状态使用动态规划求真实最优值。

比较表格型策略 \(\pi(s)\) 与 \(\pi(s,m)\)。从不同历史达到同一状态时，两者的最优值必须相同。这里不需要拟合神经网络，也不需统计置信区间；对全部可达状态穷举检验即可。

**断言：**同一充分状态下，history-conditioned 的最优值不能严格优于 Markov DP。如果出现差异，优先检查 state 是否漏了 horizon、budget、禁止重复专家的 action mask，或监督损失是否仍依赖未记录输入。

### A2. 目标相关信息被擦除的阳性对照

使用反例 C1：输入 bit \(X\)，第一轮路由记录其值后将 \(h\) 置零，目标 \(Y=X\)。可加 32 维无关高斯噪声以防把数组长度当标签。比较 h-only、h+最近专家、h+顺序历史三个控制器。

对称二分类的理论错误率为 h-only=1/2、history-aware=0。若加入标签噪声率 \(\zeta\in\{0,0.1,0.25,0.5\}\)，历史可恢复的理论准确率变为 \(1-\zeta\)，而 h-only 仍是 1/2。这给出从可预测信号到不可预测信号的连续压力测试。

此构造故意让隐藏状态不充分，不能把阳性结果作为真实 MoE 一定需要记忆的证据。

### A3. 有限函数类的可读性优势

令 \(h\) 完整保存 8 个二进制特征，目标是其 parity。历史特征包含一个构造出的累计 parity；这不增加关于目标的 Bayes 信息，却把难表达函数转成简单特征。

比较相同训练样本下的线性 h-only、小 MLP h-only、参数量匹配的大 MLP h-only，以及 h+history。严格标明 history 的构造使用输入，不读取标签。扩大 h-only 模型或训练数据后追平，支持“特征可读性/函数类”解释。

**规模：**对 8-bit 输入可穷举 256 种组合；训练泛化测试另设 12-bit 和随机划分，但不得宣称未覆盖 parity 训练分布的结果等同自然语言泛化。

## 3. 子任务 B：有限规划和价值蒸馏的能力检查

### B1. 精确延迟收益环境

使用两个 token、总预算 2、收益链 A=(0.1,9.9)、B=(6,0)。一步贪心总收益 6.1，精确两步规划为 10。再扩展到 8 个 token，每个 4 步，随机植入 1–2 条“先低后高”的收益链。

比较：固定均匀预算、一步边际收益、两步 rollout、完整有限预算 DP、监督式 \(Q^{\pi_0}\) 控制器。成本均为 1 时与非均匀成本 {1,2,4} 时分开评价。

**度量：**对精确 DP 的 regret、选中延迟收益链的比例、预测值校准、监督样本数、实际控制器时间。检查两步方法是否在候选集合包含正确路径时工作；候选裁剪排除该路径时，应当保留不可消除的缺口。

### B2. 反事实预测的不可学习边界

使用 C2 的随机目标，及标签与输入信号强度连续变化的版本。将同一批输入划分 train/validation/test，针对每个专家分别回归损失；部署时只见输入/状态。

同一张图画三条曲线：原始停止损失、标签可见 oracle 损失、held-out 控制器实际损失。信号为零时 oracle 仍很好，真实控制器必须无法突破 log(2) 的 Bayes 风险。若突破，先检查标签/随机数种子/样本索引泄漏。

本实验专门防止“先在真实标签下挑最低 loss，再声称价值模型学到了 Q*”的错误。合法目标是逐路径成本，或不看标签的 \(\pi_0\) continuation 样本成本。

### B3. 有序组合任务（可选）

用模整数仿射操作 \(F_e(x)=a_ex+b_e\pmod p\) 构造 4 个非交换专家，输入包含初值与操作描述，输出为最终结果。先固定专家函数，只训练 Router；再允许小 MLP 近似专家，研究函数近似误差和控制误差的交互。

- 训练长度 1–4；主测试仍为 1–4，但保留一些未完整出现的操作组合。
- 若测试长度 5–6，模型最大循环深度必须相应开放到 6，单独标明是外推实验，不能混入 H=4 同预算表。
- 保证单个操作和必要组件在训练中均出现；完整路径留出不等于组件留出。
- 加入重复同一专家路径、逆序路径和等长随机路径，以区分顺序价值、任务难度与长度收益。

该任务易于人为构造互补结构，结论仅限“控制机制可以学到有序组合”，不声称真实专家有预设语义。

## 4. 子任务 C：固定资源分配与动态变化必须分两组

### C1. 固定状态：求解器验证

使用 \(N=8,E=3\) 的小实例枚举 \(3^8=6561\) 个 Top-1 分配，精确计算价值、势函数、社会成本与可行性。使用 \(N=32,E=4\) 的稍大实例则通过整数匹配/最小费用流求容量受限 oracle。

得分分布设三类：均匀偏好、70% token 偏好同一专家、不同 token 各有相近的第一与第二选择。容量分别设均匀与偏斜；若总容量不足，加入成本明确的 stop/dummy 动作，不能让求解器悄悄丢 token。

比较：

1. 独立 Top-1；
2. 同步最佳响应；
3. 异步严格最佳响应，平局保持原动作；
4. 一次价格更新；
5. 软分配原始—对偶迭代 \(K\in\{1,2,4,8,32,128\}\)；
6. 价格偏好 + 硬容量修正；
7. 精确容量匹配。

**指标：**最后迭代和遍历平均的 gap 分开；逐轮超载、最大排队/溢出数、势函数单调性、社会成本和调度时间。不能拿软平均值与 hard Top-1 最后一次分配直接比较。

### C2. 状态变化：只做经验稳定性，不搬用固定问题定理

在每次实际专家调用后令下一轮价值矩阵变化，变化强度控制为 \(\delta\in\{0,0.01,0.1,1\}\)。分别测试平滑漂移、交替热点、突发热点。价格更新按 batch，hidden state 更新按专家轮，两个时间尺度明确记录。

固定问题理论预测的是 {V 固定、K 增大} 的求解误差趋势，不是 {hidden state 变化、只迭代一次} 的端到端结论。可以研究经验 drift 对误差的关系；如要新增动态 regret 理论，必须单独引入 variation budget 和假设，不能直接把原平均界换个下标。

**进入真实模型条件：**至少证明硬容量修正在所有测试实例上可行，且控制器开销没有明显超过预设调度预算。若仅求解 32 token 的均衡就需多轮昂贵同步，保留作离线 oracle，不部署。

## 5. 子任务 D：切换稳定性和信息保留

### D1. 两个稳定矩阵的切换反例

复算 C6 中的 A、B，比较 AAAAA、BBBBB、ABAB、随机路由、选择范数增长最慢的路由。循环长度依次为 1、2、4、8、16、32；使用 float64 记录范数和乘积谱半径。全部为 CPU 数值实验。

确认单专家稳定与交替不稳定后，测试以下稳定化：

- 残差阻尼 \(F_{e,\alpha}=(1-\alpha)I+\alpha F_e\)，\(\alpha\in\{0.1,0.25,0.5,1\}\)；不预设阻尼一定足够。
- 按谱**范数**归一化到 \(\|F_e\|_2\le q\)，\(q\in\{0.8,0.95,1.0,1.1\}\)。不能把谱半径和谱范数互换。
- 约束专家切换图，禁止一部分扩张组合；报告减少的动作空间和 oracle损失。

### D2. 小型学习专家

输入维度 32，每个专家为 32→64→32 的两层 MLP，4 个专家，最大 H=4；控制器为 32→64→4，并按对照决定是否加入轮数、预算和 8 维记忆。总规模远小于 1M，足以在一张卡上运行；如 overhead 主导，则 CPU 更适合。

任务选 B3 的已知组合或输入重建加可控非线性变换。比较原始 residual、每轮归一化、残差系数、适度 spectral norm、h0 anchor。先冻结专家测控制，再允许联合训练。

至少记录：任务 loss、专家 Jacobian 估计、整条路径 Jacobian、hidden norm、不同输入的表示距离、平均/最大循环深度、失败 seed 比例。Jacobian 幂迭代/随机向量只是局部估计；没有统一覆盖证明时不称全局 Lipschitz 证书。

**主要反事实：**如果严格收缩让范数稳定却让不同输入表示塌缩，便不能把它当最佳版本。使用从 \(h_0\) 注入信息的 anchor 可以降低信息丢失，但仍需重新测任务性能和是否形成共同固定点。

### D3. 与真实 LM 的连接条件

只有当真实模型出现如下现象之一，才投入此分支：更长循环导致系统性 NLL 恶化、专家序列间数值稳定性差异明显、控制器经常选择可复现的扩张路径。将稳定化作为匹配控制组加入主实验，而不是无条件给主线再添加一套约束。

## 6. 子任务 E：直接作为实现门禁的审计

### E1. 因果性

固定 prefix，替换 suffix，比较每层前缀路由和 logits。针对 global Sinkhorn、batch/sequence Top-k、当前 batch 价格、expert-choice 和 token group assignment 分别测试。系统级不同请求的共享拥塞与同一序列未来 token 的信息要区分；后者不可作为 autoregressive teacher-forcing 的部署输入。

CPU 小模型先用 float64 或 float32，关闭 dropout，固定 padding 和位置；然后主 GPU 实现设与数值精度相符的 atol/rtol。先用完全逐 token 的参考实现确定误差范围，不随意把明显路径变化解释为浮点误差。

### E2. 真实预算账本

对每个生成步骤记录新增实际 expert calls、累计 calls、预算、剩余额度；加入 C8 的合法归一化反例。账本测试必须在执行层计数，不能从“当前top集合长度”推断已发生的计算。

不同计数口径单列：独特专家参数量、总专家调用数、token-expert pairs、执行 kernel 数、padding 后矩阵元素、估算 FLOPs。所有 branch/search 的计算计入生成标签成本或部署成本中的适当项。

### E3. 顺序和架构

同一组专家比较 A→B、B→A、A→A、B→B 与并行混合；先固定全部参数。以完全相同的计算结构比较 Router，以单独表格比较架构。若 Top-2 候选是 28 个对子，计数和标签文件必须写成 pair，不得当作 8 个独立动作。

## 7. 训练、数据划分与统计协议

对于需要学习的合成任务，建议初始默认值如下，达到相应机制阈值即可停止，不机械跑满：

| 项目 | 初始配置 |
|---|---|
| 学习模型 | <1M 参数；4 experts；d=32；MLP hidden=64 |
| 训练样本 | 200k，按独立生成种子生成；重复输入需按输入组切分 |
| 验证/测试 | 各 20k；明确 IID、组合留出和噪声条件 |
| 优化 | AdamW；lr 从 1e-3 与 3e-4 二选一；batch 128 |
| 最大步数 | 10k；每 250 步验证；连续 8 次无改善可停 |
| seed | 精确枚举不需要 seed CI；学习 pilot 1 seed，确认 5 seeds |
| 候选筛选 | 不超过 4 个主要算法，先用机制oracle挑最有信息的子任务 |
| 性能统计 | 报均值、各seed散点和配对差；以原始输入为bootstrap单元 |
| 预算 | 先 profile 15 分钟；学习分支总上限建议 24 GPU-hours |

以上 GPU-hours 是人为预设停止预算，不是已经实测的完成时间。模型很小，若 dataloader/kernel overhead 主导，增加 GPU 数不会有效缩短时间；可用多卡独立运行种子，或使用向量化 CPU。

先冻结专家测试 Router，减少非平稳性；在机制成立后才开放联合训练。联合训练造成的改善必须与同样训练步数的冻结/解冻控制组比较。

## 8. 结果表与继续／停止决策

推荐产出以下四张图/表，而不是只展示一条成功曲线：

1. 充分、压缩、有限函数类三个条件的 history 增益对照；
2. oracle gap 与 held-out controller gap 随标签可预测性变化；
3. 固定/漂移价格问题的最后迭代超载、平均约束违反与真实目标；
4. 稳定化强度对 hidden norm、输入信息保留和任务 loss 的联合影响。

**通过标准：**精确反例与推导逐项一致；完整状态阴性对照无虚假历史增益；无信号目标不出现超 Bayes 性能；硬预算与因果性检查零逻辑违反；存在延迟收益时两步机制确实优于一步。

**停止标准：**如果某设计连已知小反例都不能解决，停止对应 LM 训练，先修实现；如果机制只在刻意制造的任务上成立、真实模型没有相应可学习信号，把它保留为附录，不扩成主论文。
