# 最近邻比较、可学习性与预算公式审查

日期：2026-10-25。目的：把“一个看起来有潜力的组合”转化成可以被证伪的研究问题。本文件中的反例、成本计算和建议是本项目独立分析；不是文献已经给出的实验结果。

## 1. 与 EPO 的精确边界

[EPO 原文 §5.1](https://arxiv.org/html/2605.07260v1)在固定大模型中干预最终层 router：采样等基数专家集合，用真实 token CE 形成较好／较差集合偏好，仅更新该 router，推理时无在线候选搜索。其反事实数据来自已验证正确的推理轨迹；作者在局限中也讨论了实际 token 概率作为代理的限制。

| 维度 | EPO-style 必要控制 | 本项目有序两步候选方案 | 要排除的混杂 |
|---|---|---|---|
| 基本动作 | 当前轮选择一个 Top-2 集合 | 当前轮集合、执行后状态、下一轮集合 | 不能把轮内集合排列误当执行顺序 |
| 候选空间 | 28 个集合之一（E=8,k=2） | 28×28 个集合序列之一 | 候选更多本身就提高 oracle 最优值 |
| 监督 | 当前一步实现的预测损失／偏好 | 相同总调用数下的终端损失／路径偏好 | 不能让两步法多调用专家而只比困惑度 |
| 训练对象 | 最终层单步 router | 路径价值头或因果顺序策略 | 匹配训练参数容量、数据及调参预算 |
| 推理 | 选择集合并执行 | 选首动作、执行、更新状态、再选动作 | 多步决策不得读标签或未来 token |
| 部署成本 | router 与专家正常执行 | 多次控制器、专家调用、打包成本 | 必须计控制器和实际 kernel 时间 |

这里的“EPO-style”是同骨干、同数据上的机制控制，不能写成已复现原论文的大模型数值。

### 最小且清楚的验证矩阵

1. **固定路由顺序控制**：逐轮原始 router，固定两轮。
2. **一步监督控制**：每轮只学习其一步损失改善，部署两轮。
3. **固定后续策略控制**：首动作以“执行后交给同一固定第二轮策略”的终端损失监督。
4. **两步候选蒸馏**：训练期考察有序两步路径，部署因果策略。
5. **等标注成本控制**：把两步数据开销用于更多的一步训练样本／候选。
6. **相同训练步数的普通 router 继续训练**：排除只是额外后训练带来改善。

如果（4）只胜（1）而不胜（2）或（5），不能得出“长期路径规划有价值”的结论。若（3）已与（4）相当，应优先选择（3），它减少了对未来 oracle 的依赖。

## 2. 相对 TaH2 和 MoUE，什么仍值得问

[TaH2 方法](https://arxiv.org/html/2609.35748v1)已通过预测损失的 lookahead 变化来监督继续／停止。[MoUE 方法](https://arxiv.org/html/2603.04971v1)已在 router 中加入轨迹状态。因此不能仅用“收益感知”“路径感知”“无需 RL”作为结论。

可以保留三个更窄的研究问题：

- **延迟收益问题**：在第一轮没有即时改善甚至暂时恶化的候选中，是否存在可由输入特征预测、两轮后稳定获益的路径？
- **可学习差距问题**：标签可见的路径 oracle 优势中，多少能被只见因果状态的策略恢复？
- **资源兑现问题**：路由价值的提高，能否让减少专家调用的策略在同一硬件、相同 batch 与服务负载下获得质量—延迟 Pareto 改善？

历史记忆在这三个问题中可以是一个候选输入，不预先规定它必需。如果 `h+轮次+预算+循环输入` 已与 `h+history` 相当，应删除 history 部件并保留结果。

## 3. 一个简单反例：oracle 空间很大也可能完全不可学习

令输入 \(X\) 为常数，标签 \(Y\sim\operatorname{Bernoulli}(1/2)\)，且与控制器能见到的一切状态独立。两个等成本专家路径给出

\[
p_A(Y=1)=0.9,\qquad p_B(Y=1)=0.1.
\]

如果知道 \(Y\)，选择偏向正确标签的路径，平均损失为

\[
L_{\mathrm{oracle}}=-\log0.9\approx0.10536.
\]

任何只看常量输入的确定或随机路由，在两条路径中选择，都得到

\[
L_{\mathrm{deployable}}
=-\tfrac12\log0.9-\tfrac12\log0.1
\approx1.20397.
\]

oracle gap 约为 \(1.09861\) nat，但它全部来自 oracle 看到了标签，任何可部署路由都无法恢复。若允许混合预测 \(p=0.5\)，损失可降到 \(\log2\approx0.69315\)，但这又改变了动作类；仍不能达到标签 oracle。

**实验含义**：报告 oracle gap 的同时，报告冻结策略在新文档上恢复的比例和置信区间；不能将 train oracle preference accuracy 当成任务收益。还需要 label-shuffle 负对照：打乱标签应破坏有效路由信号，而不能仍在测试集得到同等收益。

## 4. 两类多步监督目标必须区分

设 \(F(s,a)\) 为确定性专家状态更新；\(\ell(s,y)\) 为读出损失；后续策略 \(\pi\) 只依赖部署时可见信息。

### 4.1 可部署尾策略的 rollout 目标

\[
Q_H^{\pi}(s,a)
=\mathbb E\!\left[
\ell(s_H,Y)+\lambda\sum_{j=0}^{H-1}c(s_j,a_j)
\mid s_0=s,a_0=a, a_{j>0}\sim\pi
\right].
\]

监督样本可以是使用训练标签产生的实现损失，但价值头的输入不能含该标签。固定 \(\pi\) 后，该目标有明确部署含义；更新策略时要重新收集覆盖其状态分布的数据，或明确报告 off-policy 分布差异。

### 4.2 标签已知的最优尾路径

\[
\widetilde Q_H(s,a)
=\mathbb E\!\left[
\min_{a_1,\ldots,a_{H-1}}
\{\ell(s_H,Y)+\lambda C\}\mid s,a
\right].
\]

这里的最小化发生在每个实现标签已知后。一般不能把它等同于部署时可实现的最优 value，因为最小化与条件期望不能任意交换。它可以用于 **候选空间诊断／乐观教师**，但需要用学生实际 rollout 来检验是否可兑现。

这不意味着所有 oracle imitation 都无效，而是意味着：监督学习能够使用标签，控制策略的测试决策不能使用标签；且训练目标的乐观性需要量化。最经济的起点是先做固定尾策略目标，再将两步搜索作为增量。

## 5. 末层反事实的计算核算

以下为矩阵乘法近似，非 RTX A6000 实测。忽略 activation、normalization、路由、内存移动和 kernel 启动开销，乘加按 2 FLOPs。

设 \(d=512\)、词表 \(V=32768\)、SwiGLU 专家中间宽度 \(m=512\)。单 token 的数值为：

| 项目 | 公式 | 近似 forward FLOPs |
|---|---|---:|
| 一个 SwiGLU 专家的三次线性层 | \(6dm\) | 1,572,864 |
| 一轮 Top-2 | \(2\times6dm\) | 3,145,728 |
| 两轮 Top-2 | \(4\times6dm\) | 6,291,456 |
| 完整词表投影一次 | \(2dV\) | 33,554,432 |

因此，对于本项目小专家、较大词表的末层 oracle，**终端 LM head 可能比专家调用本身更贵**。只将“路径数×专家 FLOPs”作为标注预算会严重偏乐观。

完整两轮 Top-2 搜索有 784 个终端候选；共享第一轮结果后，需要 28 次第一轮动作与 784 次第二轮动作，以及 784 次词表评分。仅矩阵乘法为

\[
F_{\mathrm{oracle}}
\approx(28+784)\cdot 3{,}145{,}728
+784\cdot 33{,}554{,}432
\approx28.86\times10^9
\]

FLOPs／被标注 token，不含得到末层输入的原始骨干前向。如果还要逐步 CE、置信度或教师分布，会另有读出成本。精确全空间只用于很小诊断样本；训练标签用分支限制、候选分块和 prefix 复用。

建议顺序：

1. 首先确认完整词表 CE 的实现与原模型一致；不得为省算力悄悄换成未校正 sampled-softmax 后声称精确 oracle。
2. 缓存共享的末层输入；严格按文档划分训练／验证／测试，避免相邻 token 泄漏。
3. 小样本完整 28×28 用于测候选召回；其余使用每状态 3–4 个候选动作，明确候选是 Top-2 集合。
4. 分开记账骨干 forward、候选专家 forward、LM head、价值头训练与最终 LM 训练。
5. 实测标注 tokens/s 后再决定标注规模；若标注成为瓶颈，可改固定尾策略或只标注高不确定性但留有随机覆盖的状态。

## 6. SeqTopK 在线预算：按公开公式的反例

[SeqTopK v2 §3.2]\(https://arxiv.org/html/2511.06494v2)先累计历史分数，再在前缀 top-(mK\) 中为当前 token 选专家；旧 token 的实际执行不能撤回。正文据此声称累计实际激活不超过 \(mK\)。**仅按所展示的公式，这个界不能推出。**下面不涉及其具体代码实现，只检验公式的数学充分性。

令 \(E=4,K=1\)。两 token 的合法归一化得分为：

| token | e1 | e2 | e3 | e4 |
|---|---:|---:|---:|---:|
| 1 | 0.40 | 0.30 | 0.20 | 0.10 |
| 2 | 0.49 | 0.48 | 0.02 | 0.01 |

- \(m=1\)：prefix top-1 是 token 1 的 e1，已经执行 1 次。
- \(m=2\)：prefix top-2 是 token 2 的 e1 与 e2，又执行 2 次。
- 累计执行 \(1+2=3>2K=2\)。token 1 的调用已发生，不能因其离开新的虚拟 top 集合而取消计算账单。

因此，若本项目要求严格的前缀预算，需显式维护已花费 \(A_{m-1}\)，约束

\[
K_m\le \max(0, m\bar K-A_{m-1}),\qquad
A_m=A_{m-1}+K_m.
\]

如果需要每 token 至少一次且未来长度未知，就要将最低调用预算单独预留，或只对额外调用维护账本。这个修正保证预算可行性；不会自动保证任务质量最优。用于容量／预算实验时，同时报告计划分配、实际执行、被截断调用数。

### 不可微不等于没有前向泄漏

同一论文注明 offline 分配非因果，同时讨论 Top-k 不可微。不可微只涉及梯度，不阻止依赖未来 token 的离散选择改变当前输出。任何整序列 OT、BatchTopK 或价钱更新都应做“固定前缀、改变后缀”的前向不变性检查。要求严格自回归 NLL 的实验中，不能用一个全序列阈值再用 `detach` 作为因果修复。

## 7. 什么时候应转换成机制／负结果论文

| 观察结果 | 合理的下一步 | 不合理的解释 |
|---|---|---|
| 精确小样本 oracle 几乎无两步增量 | 检查专家多样性与循环训练是否有效；若控制充分，报告多步路径收益有限 | 直接加复杂博弈或更多路径历史期待奇迹 |
| oracle 很强，学生恢复很少 | 区分标签知晓效应、分布外状态、目标噪声与容量；优先固定尾策略 | 把 oracle 最优结果当部署性能 |
| 一步 EPO-style 已恢复全部收益 | 保留简单方法，解释多步监督为何冗余 | 继续宣称长期价值是必要成分 |
| history 只胜小线性头，无法胜等容量 h-only | 结论是读出容量／归纳偏置差异 | 宣称历史在信息论上必不可少 |
| 质量—FLOPs 改善但墙钟退化 | 考察批量／分块调度；若仍无益，限定为计算组织研究 | 宣称推理加速 |
| online 价钱只改善负载，没有质量收益 | 定位为系统调度模块；同成熟平衡法比较 | 称博弈均衡提升语言能力 |

即使多步路径方法最终无优势，严格建立“可见标签 oracle、有限容量可学习策略、硬件可兑现收益”之间的分解，也可能构成有价值的诊断研究。能否形成论文仍取决于结果的稳健性、范围和新的解释，不能提前保证。

## 8. 最终补查约束
