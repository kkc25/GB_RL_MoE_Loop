# 共同实验协议

所有 E 文件在本协议之上增补；冲突时先按本协议冻结一个版本，再修改具体实验的登记表。这里列的是拟实施设计，非已执行训练结果。

## 1. 模型与符号

| 字段 | 固定主配置 | 允许变化 |
|---|---|---|
| Transformer blocks | 12 | 扩规模单独记录 |
| hidden/head | 512 / 8 heads | 不在 Router 对照中改变 |
| experts per block | 8，层间不共享 | 仅循环内共享 |
| SwiGLU width m | 512 | 256 debug；1024 confirm |
| 词表 | 32768，train-only BPE，tied embedding/head | 所有模型同一 tokenizer |
| 每轮动作 | 8 专家中无序二元集合，k=2 | Top-1 仅合成/枚举支线 |
| 最大 FFN loop | 4 | 深度1/2/4比较，stop 后不能重启 |
| 循环块 | 最后一块 | 末4 / 全12 为E11独立扩展 |
| context | pilot 512，主1024 | 2048仅确认，重新校准预算 |
| 位置编码/归一化 | RoPE / RMSNorm，预归一化 | 所有方法相同 |

第 ℓ 块 attention 只执行一次，输出为 z_i；循环 FFN 初态 h_{i,0}=z_i。一次动作 a_t={e_1,e_2} 计算

\[
h_{t+1}=h_t+\alpha_t\sum_{e\in a_t}w_{t,e}E_{\ell,e}(\operatorname{RMSNorm}(h_t)).
\]

默认 w 对所选专家上的**冻结基准 Router logits**做 softmax 重新归一化；调路由时先只改变集合，避免预测器同时改变混合权重。候选与基准均遵守同一规则。附加均匀 w=1/2 检查可区分选择收益与权重外推，但不能跨两种规则比较 oracle gap。

共享骨干实验先在 \(\alpha_t=1/\sqrt{T_{max}}\) 与同样固定的常数 residual scale 中做小规模稳定性选择；正式所有深度共享一条已锁定的 scaling schedule。不要按照“将来实际停止的深度”事后改写已执行步长。最终层的输出 RMSNorm/head 在所有深度共享。

新增控制器在每个循环时刻输入 t 或 t/Tmax、剩余调用预算、层号；原始104,919,552参数的基准Router不因此暗增参数，新增编码参数单列。模型可选 m_t；所有 baseline 也可见其合法对应字段。规范性理论状态可含完整输入/上下文；实际控制器只用 h、t、预算等是受限可观测模型，二者不得混用。

## 2. 基础训练与冻结控制器研究

建议先建立合格循环骨干，再进行冻结专家的路由研究。

1. Debug：67M，5M–20M tokens作smoke，累计最多50M；核验loss、调度、统计，结果不用于论文主表。
2. Pilot：105M，100M tokens/seed，1 seed，只决定稳定性和数据管线；它是后续300M筛选的前缀，不重复计费。
3. 骨干筛选：105M，最多300M tokens/方法/seed；不同方法在相同 token stream 与训练 FLOPs上分别对照。
4. 确认：2–3 个关键方法、3个骨干 seeds；最高1B tokens/骨干仅在必要时开放。资源表提供 GPU-hour 门控，不能默认全部跑满。

对反事实/停止研究，主共享骨干以在 {1,2,3,4} 中采样的 loop depth 训练（相同分布固定），使短深度被训练。另有固定 R4 骨干对照，判断随机深度是否本身改变质量。多出口 deep supervision 是独立训练消融：每次额外 head 计算也计入训练 FLOPs。

默认优化器候选：AdamW，β=(0.9,0.95)，eps=1e-8，weight_decay=0.1，grad_clip=1，BF16 autocast但关键归约FP32；学习率 pilot {3e-4,6e-4}，warmup按 tokens 1%–3%，cosine decay。同一训练组用相同调参预算。它们是启动值，不保证最优。

逻辑全局 batch 主起点32768有效tokens，pilot8192；microbatch先每卡1条，实测后增加。动态卡数用累积或精确token归一化保持逻辑batch；不能把padding计入真实训练tokens。预训练可用固定batch短窗口让价格在窗口内不更新，规避当前序列未来信息。

冻结阶段需固定：所有专家、attention、norm、embedding/head、候选生成基准 Router，以及随机数/精度模式；只训练明确声明的控制器。后续联合微调必须另开组，不与冻结组混报。

## 3. 强基线的最小集合

| 基线 | 验证的问题 |
|---|---|
| 原始 Top-2，R1/R2/R4 | 简单计算扩展 |
| 逐轮独立小 Router + 相同稳定残差 | 排除“只是避免循环路由塌缩” |
| 输入 h,t,budget 的同参数 MLP | 排除容量/轮数混杂 |
| EPO-style 一步等基数CE-gap加权偏好 | 排除已有反事实监督机制 |
| 即时成本平方回归 | 区分偏好目标与值回归目标 |
| 一步soft-policy蒸馏（LatentHarness启发的受控改编） | 排除已有一步反事实动作监督 |
| MoUE-style 轻量路径状态 | 排除已有历史 Router 机制 |
| entropy / margin / hidden-change 阈值停止 | 低成本停止基准 |
| lookahead-supervised halting 机制对照 | 区分价值联合路由与停止先例 |

对于 LOOM/MoUE/TaH2，如果没有逐项复现原架构、数据和超参，必须写“机制对照”或“-style”；主文不能宣称在其论文设置上击败原方法。实现关键机制失败时保留原论文公开结果作为不同设置的相关工作，不填入等价比较表。EPO原式在E维专家logits上更新偏好并重算门权；本计划主冻结权重机制组与另设的重算权重组都要运行。28维集合头则选一个集合，是受控改编而非EPO原式。

## 4. 四个公平比较轴

**A. 机制比较：**同一冻结骨干，同一输入，同样专家调用次数、candidate pool 与候选评分预算；只变价值目标/记忆/分配规则。

**B. 参数比较：**相同总参数量或明确报告差值；独立更深/更宽 dense 模型不能被强行同时匹配所有维度。MoE层间/循环内是否共享须单独列。

**C. 推理成本比较：**同总forward FLOPs、同执行调用数、同wall clock分别给曲线，不能三者互相替代。动态方法以实际平均与p95调用数记录。

**D. 全训练成本比较：**骨干训练+探索试验+标签生成+控制器训练+联合微调。方法比较主表另列“增量成本”；重用公共骨干时摊销与不摊销都能读出。

额外给“预算转投”对照：把本方法生成标签所需的GPU小时用于基线继续训练或扩大数据。否则额外计算带来的改善可能被误归因给新路由。

## 5. 候选与标签协议

- 下一token y只能用于训练标签/离线诊断，不进入任何部署控制器或候选生成器。
- 候选必须含基准动作；其余来自基准得分前列、固定概率的探索和少量uniform样本。候选池依赖合法当前状态，不依赖y或未来token。
- Top-2候选动作数 \(\binom82=28\)；两轮完整终端路径784；四轮614656。Top-1的8^4=4096不能冒充Top-2四轮枚举。
- 一条“路径”是按时间排序的集合序列；每轮集合内部不区分顺序。跨轮允许重复专家和重复集合。
- 首先只动最后块某token，缓存最后attention输出。枚举评估采用块状LM head/logsumexp，FP32累计；不存全部候选×词表logit。
- 主监督label：固定动作后按冻结因果π0续算到相同总深度/预算所得的终局loss。样本中每个动作各记一个成本；不要先按y取min再当作Q*。
- 对候选生成、缓存、标签均记骨干hash、tokenizer hash、数据document_id、prefix position、状态版本与候选列表。骨干更新后旧缓存不能装作当前状态精确标签。

## 6. 自回归因果性必须用前向测试验证

对同一prefix拼接两段不同suffix，以完整teacher forcing计算prefix位置。其 logits、路由集合与深度在确定性模式下应相同（数值容忍由相同路径的参考计算确定）。不可微argmax不阻止前向泄漏。

所有运行时共享状态分清：

1. **同一请求的历史**可以用，未来不可以；
2. **不同请求当前可见的prefix**可用于服务调度，但输出会依赖co-batch，要明确该部署语义并测试batch-size漂移；
3. **上一已完成窗口的价格/负载统计**可以影响下一窗口；本窗口完整teacher-forcing token集合统计不能回流修改本窗口早期输出；
4. **训练学到的全局参数**与推理时从未来数据即时读取统计不同，不能混为一谈。

中间层反事实若影响后续位置，应完整重跑受影响后缀；解码带KV缓存时更要区分“仅当前token多循环FFN”与“重新计算过去token”。本计划默认不回写已经完成的过去token。

## 7. 统计与可证伪性

- 筛选1seed，最终至少3个独立骨干seeds；同骨干控制器变体共享初始化/数据拆分尽可能配对。
- 测试文档锁定；同一文档所有prefix、候选和衍生状态留在同一拆分。不能把同一输入的候选行随机分到train/test。
- 主指标是按有效token加权NLL（nat/token），PPL=exp(NLL)；不平均各文档PPL。
- 报告每seed结果与均值；文档级paired bootstrap 1000次作为同一seed内区间，不把百万token当独立样本。跨seed区间单独报告，3seeds小样本的局限写明。
- 预先选一个主要终点/预算点；其余曲线探索性展示。多个检验可用Holm校正或只对预登记主比较做确认推断。
- 主实用阈值起点0.01 nat/token；停止容忍0.005 nat/token；系统净收益目标5%。这些是计划阈值，pilot后仅可在不看正式test的前提下冻结修改。
- 轨迹顺序打乱、历史替换、candidate随机化要区分分布内干预与制造不可能状态。分布外消融只能作脆弱性检查，不能直接证明因果贡献。

## 8. 日志与验收

每run记录：配置/代码commit；seed与token流；tokens_seen；有效FLOPs估计与估计口径；实际每层每轮expert counts；probe FLOPs/head counts；NLL/PPL；峰值allocated/reserved显存；GPU型号/温度/功率/拓扑；吞吐；延迟p50/p95；训练/推理控制器占比；预算/容量违反量；重启事件。

最基本的实现验收：dense reference与稀疏dispatch数值一致；baseline动作被强制时回到baseline输出；stop从未额外计算未来专家；预算不足无法继续；打乱同一batch不改变无共享状态模型结果；prefix-suffix不变；freeze阶段专家参数hash不变。

这些检查直接针对可能推翻结论的风险，不需要围绕每个小函数编写重复实现逻辑的测试。正式GPU吞吐测量须warmup、CUDA synchronize、重复测量、相同batch/prefix/输出长度并隔离其他竞争作业。
